# 进阶地图：什么时候换引擎，换哪个

这份地图解决一个具体问题：**你下次要做的游戏，到底该用什么做。**

## 决策表：按「你要做什么」选，不按「谁更火」选

| 你要做的 | 首选 | 理由 | 别选什么 |
| --- | --- | --- | --- |
| 一款单指/双键的休闲网页游戏（本次这类） | 原生 Canvas | 60KB 级体积，零依赖，改一行就能上线 | 别上 Phaser，杀鸡用牛刀 |
| 需要物理、精灵动画、粒子、多场景 | Phaser 4（MIT） | 生态成熟，示例库几千个，遇到问题一搜就有 | 别自己写物理，你会调一周 |
| 只要极致渲染性能，逻辑自己管 | PixiJS（MIT） | 渲染层专门优化，比裸 Canvas 省心 | WebGPU 模式仍是实验态，用 WebGL |
| 要真商业化的 2D，要编辑器、要多端导出 | Godot 4（MIT，零抽成） | 可视化编辑 + 场景系统，导出桌面/安卓/iOS/Web | **C# 版导不出 Web**，要 Web 只能用 GDScript |
| 技术练手、模拟密集型、喜欢 Rust | Bevy（MIT/Apache） | ECS 架构先进，社区活跃 | 学习曲线陡，别做第一款 |
| Rust + WebAssembly 极简路线 | Macroquad | API 极少，几十行出画面 | 生态小，遇坑要自己填 |
| 想看「AI 自动生成游戏」现在到哪一步 | OpenGame 类研究框架 | 能看它怎么拆「设计→代码→调试」的技能 | 实测意图达成约 65%，**不能替你调平衡** |
| 3A 级 3D / 主机 | Unity 6 或 Unreal 5.8 | 行业标准 | 与「两周出一个网页小游戏」不在一个量级 |

## 别重复造轮子的判断标准

动手前问三个问题，三个都「是」才自己写：

1. 这东西是否**只服务于我这一个玩法**？（通用能力 → 用库）
2. 我对它的**性能要求是否低于现成方案**？（要更高 → 自己写）
3. 我能否在**半天内**写完并调对？（不能 → 用库）

《云灯》里自己写的：接住判定、追光曲线、七夜难度表、自检机器人。
这些都是「只服务这一个玩法」的东西，没有现成库能替。
星空、云海、光晕则用了最土的办法（离屏 canvas 预渲染 + 径向渐变贴图），
因为它们的性能要求低、也没必要引三方库。

## 30 天路线（假设每天 1 小时）

**第 1 周：把一款游戏跑通**
- D1–D2：抄 `demo\01-接光小游戏.html`，改成本题的掉落物（比如接金币躲炸弹）。
- D3–D4：加存档、加结算页、加一句剧情。
- D5：写机器人自检，把难度调到「新手能过前 3 关」。
- D6–D7：上线（Cloudflare Pages 或 itch.io），发朋友圈收 5 条反馈。

**第 2 周：学一个引擎**
- 只选一个：Phaser（偏 Web）或 Godot（偏客户端）。
- 目标不是学会全部，是**用它复刻你上周做的那款**。
- 复刻完你会突然明白引擎替你做了什么、代价是什么。

**第 3 周：学「手感」**
- 读 https://gameprogrammingpatterns.com/ 的状态机和对象池两章。
- 给你自己的游戏加三样东西：震屏、飘字、音高随连击升高。
- 你会发现「好玩」的 70% 来自反馈，不来自玩法。

**第 4 周：做一个小的完整项目**
- 要求：有开头、有失败、有结局、有分享。
- 这一周不要加新功能，只做打磨（加载速度、手机适配、文案）。

## 五个我踩过、你可以直接跳过的坑

1. **判定框混用**：奖励和惩罚共用一个宽度，升级会变成负收益（《云灯》返工一次）。
2. **追踪型敌人全程追**：玩家躲不掉，游戏变成随机审判。一定要留「放弃追踪」的时刻。
3. **`shadowBlur` 画光晕**：单帧掉到 20fps。改成预生成径向渐变贴图。
4. **`dt` 不封顶**：切后台回来物体瞬移，玩家一睁眼就死。
5. **插画直接放原图**：3.9MB 的 PNG 让首屏等 4 秒。压到 270KB 的 JPEG，肉眼看不出差别。

## 上线后被抓出来的三个真坑（比上面五条更值钱）

这三个都是「本地看着好好的、上线后用户在真浏览器里一点就炸」的类型，
共同点是：**你自测的路径没覆盖到它**。

### 坑六：两个 IIFE 互相看不见（`xxx is not defined`）

现象：网页一打开，控制台刷出

```
Uncaught ReferenceError: renderIdleScene is not defined
Uncaught ReferenceError: startNight is not defined
```

原因：文件里有两段独立的自执行脚本，各自是一个闭包——`CORE` 管数值/存档/剧情，
`engine` 管渲染/输入。CORE 里直接写了 `renderIdleScene()` 和 `startNight()`，
但这两个函数定义在 engine 那个闭包里，CORE **根本看不到**它们，只看到「未定义」。

为什么本地截图没发现：CORE 的 `toTitle()` 是**先显示封面浮层、再调用**这一行的。
抛错发生时封面已经铺满整屏，截图完全正常，背后那张 canvas 是空的也没人看出来。

修法（两种，任选）：

```js
// ① 定义方主动挂到 window 上（推荐，改两行）
(function(){
  var C = window.CORE;
  window.renderIdleScene = renderIdleScene;   // 函数声明会提升，写在文件头也能用
  window.startNight = startNight;
  ...
})();

// ② 调用方先判空（适合「引擎可能没加载」的场景）
if (typeof renderIdleScene === 'function') renderIdleScene();
```

**教训**：只要代码里出现第二个 IIFE，跨闭包调用就必须显式过 `window`，
或者干脆把两块合成一个闭包。「本地没报错」不等于没报错——**得看控制台，不看图**。

### 坑七：`requestAnimationFrame` 在隐藏的标签页里不跑

现象：页面打开着，canvas 一片漆黑，一像素都没画。
原因：标签页 `document.visibilityState === 'hidden'` 时，浏览器会**暂停 rAF**。
如果你的整个渲染循环只挂在 rAF 上，就是「页面在，画面没有」。

修法：加一层定时器兜底，rAF 活着时它什么都不干，rAF 死了它负责补帧。

```js
var lastTick = 0;
function loop(ts){ lastTick = Date.now(); ...; requestAnimationFrame(loop); }

setInterval(function(){                 // 200ms 巡检一次
  if (Date.now() - lastTick > 260) drawFrame();   // rAF 超过 260ms 没动 → 自己画一帧
}, 200);
```

顺带一个收益：切换场景（点「出发」）时立刻 `drawFrame()` 一次，
避免淡出淡入的空档露出黑屏。

### 坑八：没有「端到端自检」，你测的永远只是你测的那条路

《云灯》最早只测了「数值」和「截图」，所以上面两个坑全漏了。
后来加了一个 `?walk=1` 的自检参数，用真实按钮走完整个流程：

```js
// 地址后加 ?walk=1 触发；结果写进 <pre id="walklog">，末行 RESULT: PASS / FAIL
function runWalk(){
  var errs = [], log = [], step = 'boot';
  window.addEventListener('error', function(e){ errs.push('ERR ' + e.message); });
  try{
    step = 'toTitle';      C.toTitle();            log.push('title → ' + G.state);
    step = 'btnStart';     $('btnStart').click();  log.push('开始 → ' + G.state);
    step = 'btnStoryNext'; $('btnStoryNext').click();
    step = 'btnNight';     $('btnNight').click();  log.push('出发 → ' + G.state);
    // 拖动坐标换算：点屏幕 25% 处，目标应落在 720 × 0.25 = 180
    var r = cv.getBoundingClientRect(), x = r.left + r.width * .25;
    cv.dispatchEvent(new PointerEvent('pointerdown', { clientX: x, bubbles: true, pointerId: 1 }));
    if (Math.abs(R.run.target - 180) > 2) throw new Error('坐标换算不对');
    // 把一整夜跑完，走真实的 stepRun → done 路径
    var guard = 0; while (!R.run.done && guard++ < 6000) stepRun(R.run, 1/60, R.run.target);
    endNight(R.run);                       // 含 0.9 秒延迟结算
  } catch(e){ errs.push('中断于 [' + step + ']：' + e.message); }
  setTimeout(function(){                   // 异步那半段单独验
    if (G.state !== 'result') throw new Error('结算没出来');
    ...
  }, 1100);
}
```

再配一条命令行（Windows，PowerShell）把日志捞出来：

```powershell
& 'C:\Program Files\Google\Chrome\Application\chrome.exe' --headless=new --disable-gpu `
  --virtual-time-budget=6000 --dump-dom "file:///E:/.../云灯.html?walk=1" |
  Select-String -Pattern 'RESULT'
```

三个自检入口的分工，照着抄就行：

| 参数 | 测什么 | 看哪里 |
| --- | --- | --- |
| `?selftest=1` | 纯数值：七夜得分、灯芯、机器人胜负 | `<pre id="selftest">` |
| `?walk=1` | 交互链路：按钮 → 状态机 → 拖动 → 结算 → 结局 | `<pre id="walklog">` |
| `?probe=play:4` | 视觉：某一夜的静态画面 | 截图 |

**教训**：页面里一定要留一个「一条命令跑完整个流程」的入口。
它比你自己点二十次可靠，而且以后每次改代码都能重跑。

## 黑屏不是玄学，三处都堵上了

上线后第一类反馈是「点开一片黑」。查下来不是渲染 bug，是三种很朴素的情况：

1. 插画没跟着走。只拷了 HTML、漏了 `assets`，标题页封面 404，半透明遮罩一压就是黑的。
2. 浏览器把动画停掉。标签页在后台或手机省电模式，`requestAnimationFrame` 不跑，第一帧一直没画。
3. 线上是旧版本。VPS 开了 `gzip_static`，老 `index.html.gz` 还在，nginx 一直发旧文件，换 HTML 必须同时重打 `.gz`。

对应做法：

| 现象 | 处理 |
| --- | --- |
| 首帧没画出来 | 「正在点亮灯塔」载入层，第一帧画完才撤 |
| 8 秒还没画 | 明说「画面还在路上」，给重试按钮，别让人对着黑猜 |
| 脚本真崩了 | `window` 上挂 `error` + `unhandledrejection`，弹可复制诊断信息的面板 |
| 资源 404 | 只记一笔，缺图走暖色渐变兜底，不打断游戏 |
| 从后台切回来 | `visibilitychange` 补一帧 |

**教训**：黑屏是最差的错误提示。宁可丑一点，也要让人分清「还在加载」和「坏了」。

## 一句总结

做游戏最难的不是写代码，是**决定什么不做**。
《云灯》只有一条操作线（左右拖）、一种失败（灯芯耗尽）、一个目标（守满七夜）。
正因为窄，它才可能一句话出第一版，再靠几轮修补做到「画面像插画、手感站得住、七夜有结局」。

下一款别贪多，把「一条操作线 + 一个明确的失败 + 一个情绪落点」再写一遍，
你会做得比这一款快一倍、好一倍。
